# 经营决策 Skill 融合实施计划

> **For agentic workers:** 使用 superpowers:executing-plans 在当前会话逐项实施；用户已确认前文接入评估，继续执行，不重复询问接入方式。

**Goal:** 将经营决策方法并入唯一营销分析入口，补齐精确优惠情景、数值横轴图表及相应复核。

**Architecture:** 沿用五种分析方法、已读证据图及独立复核。新增受控情景工具，以已读总体实收事实绑定同一快照与范围，后端固定规则计算完整逐行或复合订单损失，代码生成条件情景和真实引用；不开放脚本、SQL 或文件工具。原有预算及成本问题继续复用 calculate_analysis。

**Tech Stack:** Node.js 22.13+、TypeScript strip-types、MySQL、BigInt 十进制运算、现有 SVG 图表和 node:test。

**Spec:** 本会话已确认的接入评估；基础合同为 `docs/superpowers/specs/2026-10-13-general-analytics-agent-design.md`。

## Global Constraints

- 保留现有未提交工作；本次起点副本与核验日志保存在仓库外私有目录。
- 用户授权范围不扩大，数据缺失不补零，失效快照及取消不能继续发布。
- 金额按行到分，情景始终是假设；历史数据、未来响应与活动执行分别表达。
- 只保留 ctf-marketing-advisor 一个分析入口和五章结构；不向模型发送 SQL、表名或凭据。
- 仅在相应数据可用时声明规则能力；逐单规则只覆盖当前筛选内复合订单的销售成交部分。

## Review Focus

- 逐行封顶和半分舍入的合计，不能用聚合克重乘参数替代。
- 同单跨门店、缺失订单键及筛选内订单部分的资格边界。
- 分组事实、旧快照、未读引用不能替代同范围真实总体基线。
- 数值情景图按比例间距绘制，原历史趋势继续只接受日期。
- 情景引用完整保留基线、规则、损失和增量参数；复核、复制和预览身份一致。
