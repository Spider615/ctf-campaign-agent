# 营销分析图表与 HTML 渲染设计

日期：2026-10-16。状态：用户已确认功能方向；本设计稿待评审，尚未实施。

## 1. 目标与验收结果

用户希望 Agent 在分析数据和回答问题时使用图表，让趋势、比较和结构更直观，并兼容 HTML 渲染。图表是回答的组成部分，用户通过正常对话获得图表，无需填写绘图表单或编写代码。

采用结构化图表与受控 HTML 渲染相结合的方式。Agent 选择图形、已有证据、展示位置和必要说明；程序解析证据、生成数据集、校验表达并绘制。正文、图表和数据表共用原始数值与范围，不由模型另写一份绘图数值。

首版达到以下可验收结果：

1. 对时间趋势、分组比较和结构构成问题，Agent 能按需要配图；仅问一个总额时仍直接回答。
2. 图表可穿插在回答正文中；查看数值、切换数据表、展开图表和查看来源无需重新查询或调用模型。
3. 分析中的图在自身核验完成后逐张出现；最终回答使用同一份数据，阶段结果和最终结论的状态清楚可辨。
4. 每个数据点都能追溯至实际读取的经营事实或文件计算结果。不存在的引用、模型自填值及错误单位不能进入图表。
5. 同一图表可使用原生组件或 HTML 预览，数值、排序、缺失值和来源保持一致；桌面和移动端均可阅读。
6. 原有文字回答、已保存会话、大结果分块、停止与重试继续有效。

## 2. 当前基础与取舍

当前 `analysis-answer/v2` 通过 `AnalysisAnswerNode` 引用事实、对象和周期，由代码格式化数字。`AnalysisAnswerBlock` 只包含文字段落、标题和列表；独立复核同时检查结论与正文。`AnalyticsProgressEvent` 当前只传工具轨迹和阶段事件，最终答案须收齐并核验后交付。

文件回答采用 `conversation-answer/v1`，正文绑定真实 `sourceIds`。`calculate_attachment` 已对完整结构化表格执行确定性运算，但公开来源主要是文字摘录，不能直接用摘录重新解析图表数值。文件计算需要增加程序维护的结构化结果引用。

页面已有 Recharts、图表组件和共用的右侧查看区。会话保存在当前浏览器会话中，恢复时重新验证回答合同。这些能力继续复用。

固定图表组件易于保证数值一致和交互可用；HTML 更适合组合图表、指标卡与说明。首版让两种展示共享结构化内容。绘图输入、数值与文本节点接受相同检查，HTML 由受控模板生成。仅增加一段可执行的模型 HTML，无法满足现有证据合同。

## 3. 首版范围

### 3.1 图形与选择原则

| 图形 | 适用问题 | 必须具备的条件 |
| --- | --- | --- |
| 折线图 | 按日或明确周期观察趋势 | 真实时间顺序、相同指标定义和兼容范围；缺失点留空 |
| 条形图或分组条形图 | 比较门店、货类、活动或周期 | 同一数值轴的单位和口径一致，比较对象及筛选可追溯 |
| 堆叠条形图 | 展示总体的组成 | 组成互斥、范围完整、指标可加总；负值采用明确的正负堆叠 |

占比只使用代码已计算并核验的比例事实；首版不提供自动归一到百分比的堆叠模式。订单去重数量、门店去重数量和均值等不能因绘图需要被相加。缺少完整构成时可展示分组比较，不能命名为完整占比。

Agent 依据问题和证据决定是否配图。图表应解释正文中的一个判断；没有新增阅读价值时保留文字或数据表。不同单位使用不同图，不提供双轴、三维图或平滑曲线。

首版覆盖实时经营数据、导入报告，以及文件中实际执行的表格计算结果。图片或文档中只有叙述性数字时继续展示原来源，不能据 OCR 或文字摘录重建一套经营图表。文件与经营数据可同时出现在回答中，首版分别成图，不合并成同口径序列。

### 3.2 HTML 的具体含义

HTML 支持由已核验图表、指标卡和说明节点组成的展示模板，允许单图与上下排列的组合布局。图表使用内嵌 SVG，模板使用随产品提供的样式。Agent 选择模板和内容引用，HTML 文本由程序生成。

原生组件提供悬浮或键盘查看数值、系列切换和数据表。HTML 预览提供相同数据的图文组合，查看数据、展开和来源入口由父页面提供。首版不依赖 HTML 内部执行 JavaScript，也不加载远程图表库。

独立文件下载、公开链接、任意 HTML 或 JavaScript 编程环境、图片生成和新的统计方法不属于本次交付。

## 4. 内容合同与兼容方式

### 4.1 可选的可视化扩展

保留 `analysis-answer/v2` 和 `conversation-answer/v1` 的文字正文合同，增加可选的 `visualizations` 扩展，其内部版本为 `analysis-visualization/v1`。未携带扩展的旧回答按原方式读取。

每个可视化项记录服务生成的 id、内容修订号、图形类型、渲染模板、正文插入位置、标题与说明节点、结构化数据、引用和来源边界。正文仍须独立回答问题，不能把关键判断只放在图里。

插入位置为当前原始 `blocks` 数组的 `afterBlockIndex`，只接受存在的段落。最终显示层在该段落后插入可视化，并在合并连续列表时保留插图边界。局部修改正文后重新校验位置和图文关联；不能默默绑定到不相关段落。

新客户端通过 `X-Analytics-Visuals: analysis-visualization/v1` 声明支持。Workers 和 Node 明确转交能力；缺少或不认识该声明时沿用原文字结果与原过程事件。该声明只决定展示能力，不改变数据权限、Skill 路由或分析完成条件。报告解读与统一文件对话均传递同一能力。

### 4.2 模型请求与程序产物分开

主 Agent 使用可选工具 `present_analysis_chart` 选择图形和已经读取的结果，不提交图表数值、任意运算表达式、SQL、HTML、CSS 或 JavaScript。提交最终回答时引用该工具生成的可视化 id 和位置。

经营数据请求引用实际 `operationId`、指标、分组维度以及参与展示的事实或对象。工具根据注册表确认这些内容属于同一结果，并记录选择方式：完整结果、代码排序后的前列、或明确的候选子集。排序规则采用有限枚举；排名与前列选择由代码对完整结果执行，不能把模型给出的对象顺序当成排名依据。

图表构建器解析原始事实、派生父链、对象、周期、币种和定义，生成只读的规范数据。每个绘图值附带真实事实引用；系列和分类名称来自已读对象、指标或周期。模型提供的定性标题与说明使用现有引用节点，并接受文字守卫及复核。

可视化 id、修订号、范围摘要、总组数、已展示组数、限制和状态由程序填写。模型不能声明自己已核验、已完整覆盖或已经得到最终认可。

### 4.3 文件计算引用

文件工具为实际表格计算登记不可变的结构化结果，返回 `calculationId`。该记录绑定浏览器身份、对话、文件 id 与版本、表格 id、操作与筛选、真实分组、数值字符串、缺失数量、单位依据和来源 id。

分组分页只是读取策略。工具在执行原有全表计算时保存完整结果；可视化构建器从该记录进行排序和选择，不能拿模型已读的一页冒充完整排名。普通读取、检索摘录或模型自填的分组值不能取得计算结果身份。

原始精确数值字符串用于标签、数据表和来源展示；只在绘图边界生成坐标数值。无法可靠转换、超出范围或单位不明确而影响比较时保留数据表，不猜测单位或丢弃精度。单位缺失的单列可明确展示为“原表数值，单位未提供”，不能据此合并其他列或文件。

文件计算仅按表格自身定义表达；不得自动将其升级为已对数的经营金额、订单或活动效果。

## 5. 图表核验与独立复核

### 5.1 数据硬核验

构建器和结果读取边界分别检查以下条件：

- 引用属于本次授权且实际读取的注册表；文件版本有效，经营事实来自对应快照。
- 所有数据点、对象、系列和周期均有真实引用；派生事实的父链完整，不能覆盖原值或单位。
- 同一数值轴的指标定义、币种、单位、人口口径和粒度兼容；跨周期或对象比较沿用原分析操作记录的对照关系和控制条件。
- 分组数量、排序、前列选择和覆盖说明与实际完整结果一致。只展示候选时明确标注选择范围，不暗示其为总体排名。
- 时间按真实日期排序；类别不重复；多个系列按分类引用对齐。未提供的值为 `null`，不连线、不填零、不把空组删除后伪装成连续趋势。
- 条形图从零开始；折线图由程序计算轴范围并展示刻度，不能由模型指定截断轴、隐藏异常点或用颜色表达未经证实的好坏。
- 堆叠图的组成可以合法相加且覆盖声明成立；比例、均值、去重计数和筛选内订单不能通过前端运算改变语义。
- 图表标题、说明、指标卡和标注中的数字、日期及对象继续使用真实引用；计划参数与历史测量分开。

前列展示清楚说明“展示范围、完整组数、排序指标”，完整数据保留在原证据中。图表限制不能改变分析总体或删减完整证据。

### 5.2 复核覆盖

最终独立复核增加每张图的审阅项，读取其标题、说明、选择规则、实际规范数据、范围、来源和相邻正文。检查比较是否成立、选择是否偏颇、图形是否暗示超出证据的关系，以及图文是否一致。

复核缓存键必须包含可视化规范数据、原始引用、选择范围、标题、说明和正文关联。图表发生变化时，相关审阅与全局一致性重新核对。遗漏图表审阅项、引用未读来源或缺少完整数据不能接受。

图形或布局请求不合法时，工具返回可修正原因且不发出图表；同一失效请求不能重复记作进展。图表是可选表达，Agent 可修正绘图方式或使用文字和数据表完成回答。来源错误仍须纠正，不能通过隐藏图表保留正文中的错误断言。

## 6. 分析中的展示与最终交付

### 6.1 阶段图表

阶段图表只展示已经完成数据硬核验的描述性结果。标题、坐标轴、来源、选择范围和说明使用程序模板，如指标名称、分组维度、周期与实际选择方式，不携带模型尚未复核的判断、因果、候选推荐或自由标注。

用户看到“已核验数据 · 分析进行中”。这表示本图数据已经检查，整轮业务结论尚未完成。模型撰写的判断性标题和说明只在最终独立复核通过后展示。这样不需要仅为预览重复调用一次独立复核模型。

### 6.2 过程事件与状态

新增有版本的 `visualization` 过程事件，仅向声明支持的客户端发送。事件携带本次请求身份、运行 id、证据代次、可视化 id、单调递增的 revision，以及 `upsert` 或 `retract` 动作。状态和身份均由服务维护。

`upsert` 提供已验证的规范内容及验证所需的引用、范围和父链；不传整轮无关方法检查、私有路径、SQL 或连接信息。接收边界验证合同、引用闭包、长度与状态后再展示。内容摘要用于去重与一致性比较，不能代替来源核验或充当授权。

`retract` 用于快照恢复、业务范围纠正或证据失效，原因由程序生成。先撤下旧代次图表，再发送新证据的结果；旧连接的迟到数据不得重新进入新代次。

同 id 的更高 revision 替换原图，相同 revision 的相同内容可去重，相同 revision 的不同内容、回退 revision 或错误请求身份都被拒绝。重试是新的请求身份，切换对话后不能更新原本不属于当前回合的消息。

### 6.3 最终结果与停止

最终 `result` 包含完整可视化扩展、规范数据和引用，不依赖客户端曾收到过程事件。只有结果完整收齐、回答硬核验和独立复核通过后，阶段图表才按最终位置进入正文，更新为最终状态；未被最终结果采用的预览撤下。

本轮以 `conditional` 交付时，图表保留其实际范围及回答条件，不升级为充分支持。`incomplete`、失败、网络中断或用户停止时，可以保留已完整接收的有效阶段图表，统一标“本次分析未完成”；它们不计入最终答案、复制文本、后续模型事实或执行输入。

数据版本失效的预览撤下，仅保留失效提示。浏览器恢复时，最终图表随回答重新核验；阶段图表只在引用证据与合同完整时恢复为“上次分析未完成”，文件引用同时重新检查权限、删除和过期。无法验证时只恢复提示。

### 6.4 大结果传输

继续复用现有完整结果的有序分块与终态校验。阶段事件只携带本图需要的规范数据和引用，不传 HTML 源码或重复的整份证据。单张图的过程事件若超过现有单行长度限制，则延后到最终结果交付，由最终结果的分块机制完整传输；本次不增加另一套图表分块协议。不得截断图表、删除原证据或让客户端绘制半张图。

渲染预算是展示上限：单回合最多六张图，每图最多四个系列；条形图最多显示三十个分类，折线图每系列最多三百六十六个点。超出时工具给出明确原因，使用有范围说明的代码前列选择、已有合法汇总或数据表。上述限制不限制查询和保存的证据规模，不能触发静默采样、趋势抽点或自动补一个新统计方法。

## 7. 交互与 HTML 隔离

### 7.1 消息与查看区

回答保持结论优先，图表紧随相关段落。图表卡片包括标题、单位与范围、绘图区、简短说明及“查看数据”“展开”“来源”入口。来源继续打开共用右侧查看区，展示周期、口径、版本、实际结果和重要限制。

展开图表复用查看区并增加适合图表的宽度规格；移动端使用全宽查看层。查看区提供关闭、Escape、焦点返回和键盘操作，图表标题、文字与数据表保持可选择、可复制。

鼠标悬浮、键盘聚焦和触摸选择可以读取同一数值。系列除颜色外使用文字、线型或标记区分。切换系列只影响显示，不能重新计算总体、改变来源或隐藏筛选状态。图表旁提供简洁文字说明，数据表始终可用。

纯文本复制保留正文，并为图表附上标题、范围和当前规范数据的文本表；不复制 HTML 源码或内部引用 id。后续模型上下文仍使用经过核验的正文与公开范围；需要具体图表事实时重新通过受控读取，不把截图、阶段预览或 HTML 当成新数据来源。

### 7.2 HTML 生成与权限

HTML 来源仅为程序维护的模板和经过验证的内容树。所有业务文字按文本节点转义；样式采用固定主题和有限布局枚举。SVG 只生成绘图需要的已知元素，不接收外部地址、`foreignObject`、事件属性或可执行片段。

预览使用 `iframe srcDoc`，设置空 `sandbox`，不开放脚本、同源访问、表单、弹窗、下载或顶层导航。通过显式权限策略拒绝相机、麦克风、位置和剪贴板等无关能力；空的 `allow` 属性不视为已拒绝全部能力。使用 `referrerPolicy="no-referrer"`。元信息中的 CSP 位于任何展示内容之前，至少采用：

```text
default-src 'none'; script-src 'none'; connect-src 'none'; img-src 'none';
font-src 'none'; media-src 'none'; object-src 'none'; frame-src 'none';
worker-src 'none'; style-src 'unsafe-inline'; base-uri 'none'; form-action 'none';
```

模板没有链接、表单、外部资源或任意 CSS 输入。图表库随应用提供，HTML 不从 CDN 拉取内容。图表操作由父页面承担，首版无需开放 `postMessage` 通道。

固定布局规格决定预览高度，内容超过高度时在预览内滚动；父页面提供展开与数据表，避免为自动测量高度开放脚本。生成或原生绘制失败时显示可读的数据表，不将整个回答改成服务异常。

HTML 生成不引入业务查询、联网取数或活动修改。只允许同一浏览器身份和当前对话已授权的内容进入组件；文件删除、过期及会话切换沿用现有隔离规则。

## 8. 模块职责与实现边界

| 位置 | 职责 |
| --- | --- |
| `app/lib/analytics/visualization-*.ts` | 无运行时依赖的请求与结果合同、证据解析、规范数据、数字格式、展示限制及 HTML 模板 |
| `app/lib/analytics/analysis-v2-evidence.ts` 与 `analysis-v2-format.ts` | 解析可选扩展、核验引用、选取证据闭包、正文位置与文本复制 |
| `agent/general-analytics-run-turn.ts` 与分析提示词 | 可选图表工具、请求能力、生命周期、最终提交与回合取消 |
| `agent/analytics-review-support.ts` 与复核缓存 | 图表审阅项、实际读取、图文一致性与变更失效 |
| `agent/attachments/` 与 `app/lib/attachments/` | 真实计算结果注册、文件版本与授权、文件图表复核及混合回答 |
| `app/lib/analytics/stream.ts`、Node/Workers 代理及客户端 | 能力转交、有序事件与分块、引用校验、取消、重试与代次 |
| `app/components/analytics/`、附件回答和共用查看区 | 图文插入、原生图表、隔离 HTML、数据表、阶段状态和来源 |

共享领域模块继续兼容 Node strip-types，不引用 React、Cloudflare 运行时、数据库或 npm 包。Recharts 和浏览器渲染依赖只放在前端组件边界；不改动原样引入的 `components/ui/` 来承载业务规则。

图形种类、轴规则和模板由 TypeScript 控制；运行时 Skill 只增加“何时用图、如何解释”的指导。执行插件及 Campaign/1811 的业务合同保持独立。图表不会扩大授权范围或把分析建议写成活动事实。

不新增客户数据或 HTML 文件落入仓库。私有审计沿用仓库外目录，记录实际图表规范、证据引用、撤回与复核结果；不保存隐藏思维。浏览器只缓存本对话允许查看的规范内容，HTML 由模板即时生成。

## 9. 验证与交付标准

### 9.1 自动化验证

1. **证据与数值**：覆盖未知和跨运行引用、派生父链、单位与币种混用、错误控制层、模型自填数值、缺失、负数、非加总指标、精度和文件分页排名。断言图表、表格和正文使用相同来源与数值。
2. **复核合同**：模拟真实工具脚本提交图表，覆盖漏读图表、错误选择、标题夸大、图文矛盾及改图后缓存失效；未知模型文本不得进入预览。
3. **生命周期与传输**：覆盖逐字节 UTF-8、图表与最终结果分块、缺块/乱序/重复、错误身份、revision 冲突、快照重开撤回、终态后追加、停止、重试和对话切换。
4. **兼容与恢复**：旧答案及无能力头保持原结果；新客户端恢复图表时重新核验。文件删除、过期或权限失效使其来源图表失效，混合回答不混用来源。
5. **浏览器验证**：使用虚构数据在桌面与窄屏检查图文位置、长标签、负值、缺值、键盘与触摸取值、数据表、展开和焦点返回。对 HTML 实测脚本、外部资源、导航和主页面存储访问均不获得能力，正文仍可选择复制。

默认验证使用固定数据、真实确定性工具、假模型脚本和已保存结果，不调用付费模型。真实模型的自动选图质量验收与本地确定性验证分开报告；只有获得授权才执行真实模型验收。

### 9.2 完成条件

针对同一能力内的新问题，正常对话即可按需得到图表，新增零条按活动名或门店名判断的分支。每个展示数据点可追溯，图文一致，图形表达复核有记录。

完整完成过程图、最终图和 HTML 三条展示路径，覆盖经营数据与文件计算；取消、快照失效和会话恢复都有明确行为。相关单测、全量测试、页面与 Agent 类型检查、lint 和构建通过，并保留桌面与移动端实际渲染证据。

交付时区分已通过的确定性测试、浏览器验证、真实模型验收和部署状态。本设计评审不代表实现、真实数据验收或发布完成。
