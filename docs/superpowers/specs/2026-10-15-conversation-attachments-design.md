# 对话附件与基于文件的回答

日期：2026-10-15

状态：用户已确认，功能已实现并完成免费验证；实际模型效果验收范围见实施计划。

## 目标与验收定义

用户需求：在现有对话框上传 PPT、Word、HTML、Excel、CSV、图片、压缩包等各种文件，并根据上传内容回答。

完成的定义是：用户上传后无需复制正文或编写代码，可以询问文件内容、比较多份资料、对表格计算并继续追问；回答能展开查看真实文件位置。收到文件、解析成功、模型实际读取、最终回答有依据是四个不同状态，界面和服务端不能混用。

上传入口不按扩展名设白名单。可理解的格式通过解析器注册表扩展；未知二进制、损坏、加密、超出资源限制的文件必须显示具体结果，不能声称任意文件均能理解。音视频转写、执行程序、运行上传的代码不属于本次交付。

## 实施前已核实的基线

- `app/components/chat/composer.tsx` 只支持字符串，空文字不能提交；尚无文件上传链路。
- 首页跳转 `/analysis`，主要对话在 `app/components/analytics/history-conversation.tsx`；绑定活动后复用 `chat/conversation.tsx` 的输入框。
- 连续对话和来源范围目前保存在浏览器会话存储中。文件正文不适合塞进该存储，也不能拼进有长度限制的历史文字。
- `/api/analytics/history` 经 Workers 转发到 Node；两侧 JSON 读取上限约为 2 MB。附件需要独立二进制上传接口。
- `general-analytics-run-turn.ts` 和 `analysis-answer/v2` 对数据库指标、引用、独立复核有严格合同，不能直接用任意文件文字充当数据库事实。
- `analyticsResponse` 提供浏览器访问标识和同源检查；Node 当前监听回环地址，分开部署时使用服务口令。
- 当前本地模型配置为 `deepseek-flash`。官方文档描述该模型及 Anthropic 兼容端点支持图像；这证明接口可用于设计，不等同于本项目已经通过图片实测。
- 当前 Docker 镜像只安装 Node 依赖，必须随功能补齐解析运行时，不能依赖开发者电脑上已有的软件。

## 设计判断

采用“私有附件存储 + 确定性解析 + 按需读取工具 + 带来源的回答”。文件本身是本会话的资料，用户问题才是任务指令。

不把完整文件反复塞进每次提示词：大文件、多文件和表格汇总会超出上下文，还会丢失位置。也不先建立全局向量知识库：本次目标是会话内使用用户资料，不是组织级知识管理。首版通过文档目录、分页读取、关键词检索和确定性表格计算完成读取；以后可替换检索实现，来源合同保持一致。

## 用户流程

1. 输入框增加“上传文件”按钮，支持多选、拖入文件和粘贴剪贴板图片；粘贴普通文字保持原行为。
2. 选中后出现附件卡片，显示文件名、大小、上传或解析状态；图片显示安全缩略图。用户可以移除、取消或重试单个附件。
3. 上传和确定性解析可立即进行。仅选择文件不触发付费模型调用；图片显示“可供识图”，不显示尚未发生的“已理解”。
4. 可附带问题发送；只有附件时使用固定问题“请概括这些文件，并说明值得关注的内容”。该默认任务不变成活动事实。
5. 上传或解析中的附件阻止本批发送，避免悄悄漏文件。失败附件可移除后发送其他文件；部分成功的压缩包明确列出未读取项。
6. 发出的消息保存附件卡片；之后说“刚才的表格”“这份方案”时可以继续读取同一会话已上传的文件。多个候选文件无法判定时才追问。
7. 回答角标可以展开“方案.pptx · 第 6 页”“销售.xlsx · 华东表 · B12:E19”“资料.zip / 方案.docx · 段落 8”等来源。Word 不伪造固定页码。
8. 清空输入框不会删除已发送文件；移除未发送文件只影响草稿。已发送文件支持明确删除，删除后阻止继续读取，既有回答标明来源文件已删除。

上传能力覆盖首页和 `/analysis`，以及统一对话绑定活动后的输入框；独立活动聊天复用同一组件和文件问答入口。附件问答不隐式变更 Campaign 或 1811 字段。

## 格式与读取合同

| 文件 | 处理方式 | 必须保留的位置与限制 |
| --- | --- | --- |
| PPTX，PPT | 新格式按幻灯片提取文字、备注、表格、分组形状和可提取的图表数据；老格式在受限转换进程中转成新格式；图形页按需渲染识图 | 幻灯片号、形状或表格位置；文字解析不能表示看懂了整页视觉内容 |
| DOCX，DOC，RTF，ODT | 提取段落、标题、表格及能定位的页眉页脚、文本框和脚注；老格式先受限转换；修订内容以最终稿规则读取 | 章节、段落、表格及单元格；不能提取的结构计入覆盖缺口 |
| PDF | 按真实页码提取文本和表格；扫描页或图表页按需 OCR / 识图 | 页码、文字块和图像区域；扫描识别结果单独标识 |
| XLSX，XLS，XLSM，ODS | 提取所有工作表、原始单元格、公式及缓存值，分开识别多张表；不执行宏 | 工作表、单元格和原始行号；空值不补零；公式与缓存值不混用 |
| CSV，TSV | 检测编码和分隔符，支持引号内逗号与换行；保存全表供受控计算 | 表头、逻辑记录号与物理行范围；保留前导零和原始文字 |
| HTML，HTM | 静态抽取标题、正文、表格和本地嵌入资源 | 标题路径、段落和表格位置；脚本不执行、不抓取外部资源；SPA 空壳明确报无正文 |
| TXT，Markdown，JSON，XML，YAML，以及可识别文本 | 保留结构或行号；禁用 XML 外部实体和实体展开 | 标题、行号或结构路径；识别到的编码及必要限制 |
| PNG，JPEG，WebP，GIF，TIFF，BMP，HEIC 等图片 | 在有对应解码器时归一化并生成缩略图，按问题提供原图或区域给视觉模型；动画默认首帧并明确范围 | 文件、帧号和区域；OCR 与画面解释区分；无法解码不能标成功 |
| ZIP，RAR，7Z，TAR 及常见压缩变体 | 受控解包后按每个子文件实际类型处理，保留目录清单 | 完整包内相对路径和子文件状态；嵌套、加密、损坏逐项说明 |
| 其他 | 检查实际文件头和文本特征，交由注册解析器；无解析器则保存元信息并标“暂不支持读取” | 不通过文件名猜内容，不把随机二进制当文字 |

Office 的 ZIP 容器须先识别 OOXML，不能把 XLSX / PPTX / DOCX 当成普通压缩包。实际内容与后缀不符时按实际类型解析并给出提示。

表格汇总必须处理满足条件的完整记录，由代码执行筛选、求和、计数、去重、均值、极值与分组；禁止用检索到的几行推算全表。保留数值、显示文字和单位；金额口径明确后用十进制定点计算。跨表比较先核实字段、单位、币种和粒度，未知业务含义不能自动补齐。

公式默认使用文件内已有缓存值并明确其状态；缓存缺失或是否已更新无法判断时不能当成当前计算结果。首版不自动重算任意 Excel 公式，也不解析外部工作簿链接。

## 系统边界和数据流

```text
共享输入框 → Workers 上传网关 → Node 私有文件存储
                                  ↓
                         受限解析进程 → 结构块 / 表格 / 图像
                                  ↓
用户问题 + 附件引用 → 对话编排 → 授权读取 / 检索 / 计算 / 识图
                                  ↓
                         引用校验 → 最终回答与来源卡片
```

### 上传与存储

- 新建 `/api/analytics/attachments` 上传网关和附件元信息、内容、删除接口，复用 `analyticsResponse`。二进制单独流式转发，不能通过提高全部 JSON 请求上限实现上传。
- 浏览器先初始化访问标识；Workers 从 cookie 得到 owner，覆盖内部身份头后转发，绝不采信客户端提供的 owner。
- Node 附件接口复用服务鉴权；无服务口令时仅允许回环监听，不能为上传开放未鉴权公网 Node 接口。
- 每份附件绑定 `{ owner, conversationId, attachmentId }`。读取、列表、删除、重试、模型工具调用都校验三者，不以随机 ID 代替权限验证。
- 原文件、解析产物、图像和表格保存在仓库外 `ATTACHMENTS_DIR`；本机默认用户应用数据目录，容器默认 `/data/attachments`。这是新增的文件存储职责，既有 Campaign 对话落库职责仍在 Workers。
- 每个附件有原始内容 SHA-256、解析器版本、不可变内容版本、原始名称、实际 MIME、大小、覆盖情况和状态；内部存储使用随机名称，原始文件名只用作展示。
- 元信息使用原子写入和单附件任务锁；重复上传按 owner、会话、原始名称及内容哈希去重，不向其他访问者暴露哈希命中。
- 浏览器会话只存附件 ID、文件名、大小和状态快照；恢复后由服务端重新校验。刷新可以继续使用，切换到另一会话不能读到原会话附件。
- 首版保留期为最后使用后 30 天，服务启动及运行期间定期清理；上传中断的临时文件和未完成任务需回收。删除会使文件、子文件及解析产物不可再读取，正在执行的问答收到失效信号。
- 下载始终经过权限检查并使用 `Content-Disposition: attachment`；来源预览只显示转义文字或生成的图片，不在产品源站执行上传 HTML / SVG。

### 解析进程

- Node 负责文件状态、任务队列和取消，调用固定 Python 解析入口；Python 与转换器不接收密钥或数据库配置。
- 计划采用 `python-docx`、`python-pptx`、`openpyxl`、`pdfplumber`、Pillow 及安全 XML / HTML 解析库；LibreOffice 处理旧 Office 格式和必要渲染，libarchive 处理压缩格式，Tesseract 提供本地 OCR。实现时锁定可复现版本，并随镜像安装全部依赖。
- 统一中间结构为 `DocumentBlock`：块类型、原始文字、章节路径、页码或幻灯片号、表格位置、图像引用、包内路径、解析方式及警告。
- 文档按结构切块；表格另外保留完整结构化数据与类型，不把模型读到的切片当成全部数据。
- 图片和扫描内容在用户发送问题后按需读取；视觉模型优先复用当前 DeepSeek 服务的图像接口。原图内容经服务端读取后传递，不能要求用户把私有文件变成公网 URL。
- 全文概括须遍历文档目录并覆盖全部结构块；只读部分内容时必须说清覆盖范围。视觉描述及 OCR 保留原图来源，数值识别有疑点时不给出确定性结论。
- 错误分为无正文、加密、损坏、不支持、资源超限、可重试服务失败；一个子文件失败不阻断其他可读取子文件。

### 问答与证据

- 新建文件对话请求，携带原始问题、会话 ID、附件 ID 及有限历史；不接受客户端上传“解析后的权威内容”或本地路径。
- 纯文件问题无需历史数据库；现有“未启用数据库就拒绝”的入口检查须避开文件问答。
- 现有无附件数据库请求继续使用原合同和原校验。附件及混合回答使用独立协商的 `conversation-answer/v1`，在流式结果联合类型中新增分支，不改写 `analysis-answer/v2` 的语义。
- 提供固定工具：列出附件结构、分页读块、检索附件、按真实字段做表格计算、读取图像。工具只能访问当前授权附件，不能开放 Bash、任意文件系统或任意 SQL。
- 混合问题按需通过受控工具调用现有经营数据分析能力，保留原始问题和实际筛选；返回的 `AnalysisAnswer` 仍先通过原有数值与业务复核。新回答引用这些已核验事实时保留其原始来源，不能拿文件内容扩大数据库授权。
- 文件回答节点区分普通文字、原文引用、表格计算事实、视觉观察和已核验数据库事实。服务端维护本轮实际读取集合；引用必须来自该集合，原文引述必须与版本内原文一致，计算数值由代码生成。
- 最终内容接受基于真实来源的语义检查，区分“文件声称”“数据计算得到”和“建议 / 假设”；硬校验不通过时不得把模型原始正文当备用答案发给客户。
- 对话中的“谢谢”“这个月销售额多少”等快速路径仅在不依赖附件时适用，不能忽略用户随本轮发送的文件。
- 文件中的“忽略系统提示”“调用工具删除数据”等文字始终作为资料，不授权动作。上传的方案、优惠、会员分组和日期不能直接写回执行事实；涉及 Campaign / 1811 的人定字段继续通过已有用户原话或明确确认合同。
- NDJSON 只发送真实的上传、解析、读取、计算、核验过程及最终答案，不发送全文、内部磁盘路径、凭据和隐藏思维。

## 资源默认值

以下是首版工程默认值，当前在附件合同常量中统一调整；“各种文件”指格式可扩展，不表示无限资源。

| 项目 | 默认值 |
| --- | --- |
| 单个原始上传文件 | 25 MiB |
| 单条消息文件数 / 总上传大小 | 10 个 / 100 MiB |
| 单会话原文件存储配额 | 500 MiB |
| 单包累计展开大小 / 普通文件数 / 嵌套深度 | 250 MiB / 100 个 / 2 层 |
| 单个展开子文件 | 100 MiB，仍受解析内存与记录数限制 |
| 每个访问者 / 全局并发解析任务 | 2 / 4 |
| 单个解析任务 / 内存 | 120 秒 / 512 MiB；不改变对话 Agent 无总墙钟时限的合同 |
| 单文件结构化表格记录数 / 单页或单图解码像素 | 200,000 条 / 40,000,000 像素 |
| 单回合默认视觉读取量 | 8 张图像或渲染页，按实际需要读取；超过后给出已读范围，不声称全本已读 |
| 文件保留期 | 最后使用后 30 天 |

所有压缩包限额累计覆盖整棵子文件树；实际展开字节数在写入时计数，不信任目录声明。拒绝绝对路径、`..` 越界、符号链接、硬链接、设备文件和特殊路径；OOXML 解析同样适用解压资源限制。

解析器必须有进程级 CPU、内存、文件和输出限制；不以子进程本身当作完整沙箱。Linux 部署用受限用户及无网络的解析隔离运行时，本机用对应的受限执行器；缺少必要隔离能力时明确启动失败或禁用相应解析器，不能默认放开。取消与超时终止进程树并清理工作目录。XML 外部实体、Office 宏、外部链接更新和 HTML 脚本始终关闭。

## 修改边界

- 输入与展示：共享 `composer.tsx`、附件卡片及来源预览组件、`history-conversation.tsx`、`conversation.tsx`、`history-message.tsx`。
- 客户端合同：附件草稿状态、上传客户端、消息附件引用、浏览器恢复、流式回答联合类型。
- Workers：附件接口、同源与 owner 转发、二进制流和取消、文件对话入口；共享领域模块仍不依赖 Node 或 npm 包。
- Node：附件 HTTP 分发、私有存储、解析队列、Python 入口、受控读取 / 计算 / 识图工具、文件回答校验和现有数据库能力适配。
- 部署：Docker 解析依赖、私有持久卷、配置示例及启动前依赖检查；更新 AGENTS.md 中相应的存储和协议说明。
- 不自动导入上传表格到 CTF MySQL，不修改历史报告或数据版本，不通过文件提取绕过活动事实守卫。

## 验收用例

1. 含文字、图表和表格的 PPTX，可回答指定幻灯片问题，引用精确页；DOCX 可引用段落和表格；旧 PPT / DOC / XLS 通过独立样本验证转换。
2. UTF-8 / GB18030 CSV、含引号换行的 CSV、多工作表 Excel 可正确读取；求和使用全表，保留缺值、前导零和币种，不使用模型口算。
3. Excel 公式有缓存、无缓存、存在外部链接三种情况都显示真实边界；不能把公式字符串当数值。
4. HTML 静态正文、表格可回答；带脚本、事件属性、远程资源及 SPA 空壳不会在产品中执行或偷偷联网。
5. 图片可回答文字及画面问题；扫描 PDF 的被读取页有 OCR 或视觉来源；没有实际读取的页面不出确定性结论。
6. 混合 ZIP / RAR / 7Z 可逐子文件提问并保留完整路径；部分损坏、加密或未知格式逐项显示，不冒充整包读取成功。
7. 单附件、多附件、只有附件、移除、拖拽、粘贴图片、键盘发送、中文输入法、手机窄屏和停止操作可用。
8. 上传失败可重试，回答失败不丢文件；刷新后可追问，切换会话不串附件；文件过期或删除给出明确提示。
9. 跨 owner、跨会话、伪造 ID、伪造内部身份头、路径穿越、符号链接、解压炸弹、XML 实体、超大图片、提示注入均有确定性测试。
10. 只有文件且数据库未配置仍可回答；原有无附件查数、分析、活动执行流程及 v2 客户端保持兼容。
11. 所有文件引用均来自本轮实际读取的版本；原文、表格计算、视觉观察与数据库事实分别核验；既有数据快照与业务复核不被绕过。
12. 开发机和交付镜像分别执行样本解析，不能把“本机安装过”当作部署可用。上传、解析、检索、计算和最终回答记录分段真实耗时。

回归包括新增确定性解析 / 存储 / 接口 / 引用测试，以及 `npm test`、两侧 TypeScript、lint、build 和浏览器交互验证。先用假模型和合成文件完成免费验证；真实视觉或模型验收单列调用范围与结果，不把静态通过称为模型效果通过。

## 外部接口依据

- [DeepSeek Vision](https://api-docs.deepseek.com/guides/vision/)：`deepseek-flash` 图片输入、支持格式及 Anthropic 兼容块结构；本项目仍需联调验证。
- [openpyxl 读取合同](https://openpyxl.readthedocs.io/en/stable/api/openpyxl.reader.excel.html)：`data_only` 读取已有公式缓存，不等于重新计算公式。
- [python-pptx](https://python-pptx.readthedocs.io/en/latest/user/quickstart.html)：PPTX 文字与表格的结构访问。

## 评审结论范围

本规格作出工程默认判断，没有把格式、大小、检索实现和存储方式作为菜单交还用户。规格评审时尚未验证项目图片接口联调、最终依赖锁定版本、隔离执行器和样本质量；实施后的最新记录见 `docs/superpowers/plans/2026-10-15-conversation-attachments.md`。

实现采用 macOS Seatbelt、Linux Landlock ABI 6 与 seccomp；缺少隔离能力就返回环境错误。LibreOffice 的本地管道与缓存置于独立任务目录，Linux 通过随依赖编译的探测适配组件选择该目录，IP 和外部 UNIX 出站仍被阻断。适配依据为 [LibreOffice 管道实现](https://github.com/LibreOffice/core/blob/master/sal/osl/unx/pipe.cxx)。图片识读及含图片的独立复核默认使用 Flash；主分析配置为 Pro 时也不会把原图交给不支持图片的模型。实际付费模型效果验收单列，不以假 SDK 的通过代替。
