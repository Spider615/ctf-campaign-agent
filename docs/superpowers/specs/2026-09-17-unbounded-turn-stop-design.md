# 无总时长上限与主动停止设计

## 1. 背景

当前模型回合同时受两层总时长限制：Agent 服务在 120 秒后中止 SDK，Workers 在 150 秒后中止到 Agent 服务的请求。长任务即使仍在正常分析或调用工具，也会被固定墙钟截断，并在对话中落成红色超时错误。

对话页已有三个错峰跳动的小点，但只在尚未出现工具轨迹时显示。一旦 Skill 或业务工具开始执行，等待指示器就消失，工具卡与输入框之间出现空白。输入框在执行期间只会禁用发送按钮，没有主动停止入口。

## 2. 目标

- 模型回合不再因为累计运行秒数而自动失败。
- 保留 `maxTurns = 12` 的逻辑轮数上限，避免 Agent 无限进行模型往返；它不是时间限制。
- 工具轨迹出现后、正文开始流式输出前，继续显示三个点的波浪等待动画。
- 执行期间把发送箭头切换为可点击的方形停止按钮。
- 停止必须真正终止浏览器、Workers、Agent HTTP 服务和 SDK 中的同一回合，不能只隐藏前端动画。
- 用户主动停止不显示红色失败；在原子提交开始前停止时，不落库未完成的 Agent 修改。

## 3. 非目标

- 不修改 Campaign Brief、主题提议、1811 提议或任何业务确认规则。
- 不改变 `maxTurns = 12`。
- 不保存未经最终协议与领域校验的局部回复、工具结果或草稿修改。
- 不承诺消除上游模型、网络、进程或托管平台自身产生的错误和断连。

## 4. 运行时生命周期

### 4.1 不设应用层总秒数上限

删除 Agent runner 的 120 秒定时中止，以及 Workers 请求 Agent 服务时的 150 秒 `AbortSignal.timeout`。回合可以持续到以下任一终态：

1. SDK 返回成功结果；
2. SDK 达到 12 个 agentic turns；
3. SDK、模型提供方或网络返回真实错误；
4. 用户点击停止；
5. 浏览器页面关闭、导航离开或连接断开。

界面可以持续展示已用时间，但不得仅因总用时较长而把回合判为失败。

### 4.2 端到端主动停止

每个流式回合在浏览器创建一个独立 `AbortController`。信号按以下链路向下游传播：

```text
Conversation
  -> postTurnStream(fetch signal)
  -> Workers turn route(request/cancel signal)
  -> runtimeDeps / runAgentRemote(fetch signal)
  -> Agent HTTP response close signal
  -> createAgentRunner(external signal)
  -> SDK abortController
```

任一上游断开都中止下游工作。Node Agent 服务在响应已关闭后不得继续写流事件；SDK 子进程收到 abort 后必须结束。

`runTurn` 把“主动取消”与普通异常区分开：取消直接向上抛出，不走现有 `agent_error` 落库分支；最终提交前再次检查 signal，避免结果返回与停止点击同时发生时仍写入版本。

原子提交调用是本回合的线性化点：停止若先于 `store.commit(...)` 调用发生，则取消获胜且本回合不写入；一旦原子提交已经开始，则提交获胜，不能把正在执行的 D1 batch 安全地拆回半轮。这个极窄竞态下仍只会出现“整轮提交”或“整轮不提交”，不会出现局部工具结果或半个版本。客户端后续请求如遇 seq 变化，沿用现有 409 刷新机制取得最终快照。

### 4.3 停止后的界面与数据

- 当前流式正文、临时工具轨迹和等待状态立即清除。
- 尚未越过提交线性化点的草稿修改和版本全部丢弃；D1 仍保持回合开始前的原子快照。
- 普通文字回合只在输入框仍为空且服务端快照中没有提交该句时，把刚发送的文字恢复到输入框；不得覆盖用户等待期间输入的新草稿。
- 若停止与提交竞态中原子提交获胜，下一次 409 对账刷新到新快照并把该句视为已提交，不显示红错、也不把同一句重新塞回输入框。
- 首次自动理解被停止后，页面以本地停止状态解除等待和输入锁定，并提供“继续理解”入口；用户也可以直接补充内容。
- 主动停止不显示红色错误。真实模型、网络或协议错误继续使用现有错误与重试流程。

## 5. 界面设计

### 5.1 三点波浪

等待指示器由三个同尺寸圆点组成，沿纵向依次起伏，并用错峰 delay 形成从左到右的波浪。它在以下阶段可见：

- 请求已经开始，尚无工具轨迹；
- 已出现 Skill/工具轨迹，但尚无安全的正文 delta；
- 模型从工具调用返回，正在组织最终回复。

正文开始流式显示后隐藏等待指示器。`prefers-reduced-motion` 下保留三个静态点，避免强制动画。

### 5.2 停止按钮

非执行状态保持现有蓝色圆角发送按钮和向上箭头。流式回合执行时，同一位置切换为可点击按钮：

- 图标为居中的实心小正方形；
- `aria-label` 为“停止生成”；
- 保持至少 44 × 44 像素的点击区域；
- 点击后立即禁用，防止重复取消；
- 非模型回合仍沿用现有 busy 禁用行为，不展示停止入口。

## 6. 错误边界

- `AbortError` 或仓库定义的等价取消错误代表主动停止，不能转换为“连不上 Agent 服务”或“Agent 超时”。
- SDK 达到 `maxTurns` 时继续显示“Agent 步骤太多，没在限定步数内完成”，与时间无关。
- 上游模型、网络、协议解析和业务校验错误保持现有可重试错误。
- 取消后到达的迟到 trace、delta 或 snapshot 全部忽略，浏览器 reader 主动取消并释放锁。

## 7. 测试与验收

### 7.1 自动化测试

- Composer 在流式 busy 状态显示方形“停止生成”按钮，普通状态仍显示发送按钮。
- 工具轨迹存在且正文为空时，三点等待指示器仍渲染。
- 浏览器流被 abort 后取消 reader，并以取消错误结束，不解析迟到事件。
- Workers 将请求取消信号传到 Agent fetch；提交线性化点之前的取消不落 `agent_error`、用户消息或新版本。
- 取消与原子提交并发时有明确且经过测试的“先到者获胜”语义，绝不产生半次提交。
- Agent HTTP 连接关闭后中止 SDK controller，且不再写 response。
- Agent runner 的外部取消与 SDK 错误可区分。
- 代码中不再存在 120 秒 Agent 总超时或 150 秒 Workers 总超时；`maxTurns` 仍为 12。

### 7.2 浏览器验收

1. 发起一个会调用 Skill 和多个业务工具的回合。
2. 工具卡出现后，卡片下方仍可见三点波浪。
3. 输入框右下角显示方形停止按钮。
4. 点击停止后动画、临时正文和工具轨迹立即结束，输入区恢复可用且不出现红色错误。
5. 重新发送后可以正常完成新回合。
6. 让一次回合运行超过 120 秒，确认应用不会因累计时间自动终止。

## 8. 约束

- 继续保持“整轮完成后一次提交”的原子写入模型。
- 不把真实模型 thinking block 暴露给界面；三点动画只表示回合仍在运行。
- 取消链路不得依赖单进程全局 session registry，以兼容 Workers 的执行环境。
- 所有新增界面文案、错误信息和代码注释使用中文。
