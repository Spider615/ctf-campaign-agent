# 营销分析回答：自由组织正文，数字用引用

日期：2026-10-19
取代：`2026-10-18-analytics-playbook-orchestration-design.md` 第 3.4、3.5、3.6 节（结论与答案、措辞复核、图表）。计划、校验、执行（3.1–3.3）不变。

## 1. 问题

现在每个回答都是同一套板块：主结论、关键数据表、主要发现、图、建议、暂时不能下的结论。

- 问「库里有多少活动」，答案是一个数，却也配齐了全部板块，重点被淹没。
- 每次都出现「暂时不能下的结论」「建议」，读起来像填表，不像营销顾问。
- 板块顺序和数量是代码写死的，模型没法根据问题调整。

用户要的是：回答怎么组织由问题决定，没有固定板块。

## 2. 约束

- **数字必须来自数据库。** 这是演示给周大福看的分析助手，数字错一个就失去信任。上一轮之所以用「措辞 + 占位符」，就是为了保证这一点，这一条不放松。
- 计划、校验、执行不动。语义层对账 56/56、各题耗时、调用次数不能变差。
- 旧会话里存的 v3 答案要能继续显示。

## 3. 设计

### 3.1 正文由模型自由写，数字写成引用

模型提交一篇 Markdown 正文。可以有标题、段落、列表、加粗，长短、分几段、写不写建议，全看问题。

正文里不能直接写算出来的数，要用引用：

```
8月有成交的活动共 {{m1.distinct_count}}，其中地区营销活动 {{m4.distinct_count|campaignType=地区营销活动}}。
```

引用的写法：`{{节点.指标.角色|维度=取值,维度=取值}}`

- 角色可省略：对比节点默认差额，汇总节点默认数值，和现在的规则一致。
- 分组可省略，省略时取总体行。
- 代码按引用查到事实，替换成格式化后的数值（带单位）。查不到、分组不唯一、值为空的引用，退回给模型改一次；第二次仍不通过的，那一句删掉。

不允许的数字检查（digitGuard）、业务名称和原话里的日期可以照写、重复单位去重，这些都沿用。

方向判断（assert）取消。上一轮它挡掉过大量正确的结论（只是想报一个数、想说「最多」却写成别的），而真正的方向错误，靠措辞复核看「依据」里的正负号更直接。

### 3.2 表格和图用引用指定

模型想放表格或图时，写一个块，指定要哪个节点、哪个指标、按哪个维度：

```
::: table m1 rows by offer top 6
::: chart m3 amount_per_day by district top 8
```

- 代码从节点结果取数据生成表格或图，模型不手写表格里的数。
- 块写在正文哪里，就显示在哪里。不写就没有。
- 图的类型由数据形状决定：按日期是折线，按分组是条形；对比节点画偏离。

### 3.3 重点数字

正文第一段只有一个引用时，界面把这个数放大显示在最上面（沿用上一轮的显示）。第一段有多个数时不放大。

### 3.4 什么时候写什么

提示词里给方向，不给模板：

- 问「多少」：第一句就是那个数，再补一两句构成或口径。没有必要就不写建议。
- 复盘、对比：先说结论，再给关键差异，必要时放表格或图。
- 做决策：开头给推荐，再给依据和风险。
- 找机会：几条有数据支撑的发现，每条说清为什么值得做。
- 数据里缺的东西，只在影响这个问题的答案时提一句。

### 3.5 复核

措辞复核保留，但对象从「每条结论」改成「整篇正文」：检查有没有答非所问、把相关写成因果、引用的数和文字说的方向是否一致（例如文字说「增长」，引用的变化却是负数）。复核给出改写后的正文，改写同样走引用校验。

调用次数不变：计划 ≤2、补充计划 1、正文 1（同一调用内可改一次）、复核 1，一共 ≤6。

### 3.6 出处

每个引用替换后的数字可以点开，看到这个数的来源、范围和怎么算的（现有出处面板）。口径说明和分析步骤也留在出处面板里，不进正文。

## 4. 答案结构

新版本 `analysis-answer/v4`：

```ts
type PlanAnswerV4 = {
  schema: "analysis-answer/v4"; runId; question; status: "answered" | "partial" | "unavailable";
  body: Array<
    | { kind: "markdown"; text: string; refs: Array<{ start: number; end: number; factIds: string[] }> }
    | { kind: "table"; title: string; columns: string[]; rows: Array<{ cells: string[]; factIds: string[] }> }
    | { kind: "chart"; chart: ResolvedVisualization }
  >;
  keyFigure?: { value: string; factId: string };
  assumptions; definitions; plan; review; evidence; trace?;
};
```

- markdown 块里的数字已经替换好；`refs` 记录每个数字在文字里的位置和对应事实，界面据此做可点击的出处。
- 证据仍只保留被引用的事实及其推导来源。
- v3 答案按现有界面继续显示，不做转换。

## 6. 风险

- 模型可能写得太长。提示词限制正文 600 字以内，代码超过 1200 字截断并标记。
- 模型可能不写表格或图。这是允许的；验收时看五个测试问题是否该有的都有。
- 去掉方向校验后，方向写反只能靠复核发现。复核看得到每个引用的正负号，验收时专门抽查。

## 7. 验收

- 五个测试问题加「库里有多少活动」：每题 ≤6 次调用、≤8 分钟。
- 「多少活动」第一句就是 442，没有建议和不能下的结论。
- 复盘、决策类问题有表格或图，有依据。
- 抽查每题的数字和独立 SQL 一致。
- 旧会话里的 v3 答案仍能打开。

### 验收结果（2026-10-19，DeepSeek flash，浏览器并发）

| 题 | 耗时 | 调用 | 回答组织 |
|---|---|---|---|
| S1 七夕复盘+大区分区 | 256s | ≤6 | 先说整体，再用分区表指出局部亮点和问题 |
| S2 克减30 vs 50 | 246s | ≤6 | 开头给推荐（冲销售 50 元档、保毛利 30 元档），再讲控制了什么、哪些结论不能下 |
| S3 找新角度 | 326s | ≤6 | 五条带数据的发现 |
| S4 会员等级 | 156s | ≤6 | 先说明没有等级数据，再给会员 / 非会员对比 |
| S5 金价 | 121–236s | 6 | 先指出牌价没涨，再讲增量来自件数和让利，附牌价逐日走势 |
| 有多少活动（含追问） | 34–122s | ≤6 | 最上面放大「442个」，补一句口径，追问时附头部活动表 |

抽查与独立 SQL 一致：活动数 442（有成交）/ 551（明细中出现过）/ 786（活动 × 期次）；S5 每克牌价下旬对上旬 -0.03%、-0.35元/克（共同门店）。

验收中发现并修复：模型把正文直接说出来不调用工具（含引用时按正文采用，否则补交一次）；计划范围内的日期可以照写；方向词与填值正负相反时删句；对比节点说明写明目标、参照和「差额 = 目标 − 参照」；表格把角色当指标时的提示；拆解节点默认取贡献。
