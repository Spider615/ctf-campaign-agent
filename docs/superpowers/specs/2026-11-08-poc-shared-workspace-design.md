# POC 共享工作空间

用户要求：解决更换浏览器后记录为空的问题，保持 POC 简单，不引入账号。

## 行为

- 同一部署的分析 API 使用固定的共享空间标识，不依赖浏览器 Cookie。
- 对话、导入快照和报告保存在现有 D1；共享空间可以读取旧浏览器标识名下的记录，不修改原始快照或报告。
- 相同对话编号的历史副本只显示最近更新的一份；继续保存沿用已有记录。删除会清除该编号的正文并在原表留下轻量标记，阻止其他浏览器的旧缓存重新补写；新浏览器加载时一并移除已删除的缓存。
- 对话范围仍区分智能问答和各活动的文件问答；不能将已有编号写到其他范围。
- 新附件写入共享空间目录；旧附件在原位置按对话编号兼容读取，容量限制、有效期、解析隔离保持有效。
- 浏览器缓存和上次打开的对话仅作本地偏好；新浏览器从服务端读取记录。

## 实现边界

共享标识保留 UUID 格式，兼容 Agent 的附件与执行记录协议。存储层保留原有标识参数，以便读取既有记录；只有应用确定的共享标识能够读到本部署全部历史记录。写请求继续检查同源，内部管理登录和 Agent 服务令牌不变。

无需账号、额外配置、数据库迁移或文件搬运。不增加跨浏览器实时协同编辑；打开或刷新页面时加载服务端记录。不同部署仍使用各自的持久化数据库和附件目录。

## 验证

回归覆盖不同 Cookie 和无 Cookie 请求归属一致、跨浏览器读写、旧数据和报告可读、对话去重与删除、范围边界、旧附件下载与删除、跨对话不可读。运行相关测试、两侧类型检查和构建；不调用模型或真实经营库。
