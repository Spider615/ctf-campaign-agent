# 智能洞察：活动关系图谱 设计

依据：2026-10-19 范兆然 × 刘俊杰《营销活动Agent产品迭代对齐会议》纪要与会上草图；数据为 `ctf_sales_202508.sales_detail_202508`（2025 年 8 月，128.8 万行，5934 店，551 个优惠名、933 个期次）。文中数字均为 2026-10-19 对 127.0.0.1:3308 实测，标「推断」的未经业务确认。

## 1. 要解决的问题

现有营销分析是「用户先问，Agent 再答」。没想好问什么的运营打开页面无从下手。洞察模块反过来：先把「哪些因素和活动表现有关、关系多强、哪里反常」摊成一张图，用户点着看，看到想动手的地方再追问（what-if）或直接去建活动。

产品闭环：**洞察 → 构建 → 发布 → 回到洞察看结果**。构建就是现有 ICS-1811 对话建活动；发布本期做演示壳。

## 2. 图谱的中心不止一个：目标指标

「活动效果」不是一个数。克减类活动让利换销量，卖得多和让得多是同一件事的两面；只看销售额会把门店多、货贵的活动排在前面。所以图谱中心做成**可切换的目标指标**，每个目标指标都是一张以它为中心、四周挂维度的图（结构同会上草图）。

### 2.1 指标目录

按「活动想达成什么」分 7 族。数据列写的是能否从 8 月宽表算出来。

| 族 | 目标指标 | 口径 | 数据 |
|---|---|---|---|
| 卖得多 | 活动增量（默认中心） | 同货类、同门店范围内，活动成交的日均实收/克重 相对一般開單的差 | 有 |
| | 每店实收、日均实收 | 已在语义层 | 有 |
| | 活动渗透率 | 挂该优惠的实收 ÷ 同店同期总实收 | 有 |
| 让得少 | 每克让利 | 一般開單每克实收 − 活动每克实收（同货类同材料、同日对齐金价） | 有 |
| | 折扣率 | （牌仔价 − 实收）÷ 牌仔价 | 有，牌仔价口径待确认 |
| 赚得多 | 毛利率、每店毛利 | 源字段零售毛利 | 有，口径待确认 |
| 买得大 | 单件克重 | 克重 ÷ 件数 | 有 |
| | 单均实收、连带率（单均件数） | 门店 + 单号去重 | 有，缺单号 2.9 万行不计 |
| 换得多 | 以旧换新率 | 订单中含回收金行的比例；回收抵扣额 | 有（`回收金标识`） |
| 去库存 | 老货动销占比 | sku 年龄 ≥ 365 天的实收占比 | 有，sku 年龄缺 10.4 万行 |
| | 重点系列占比 | 重点系列实收占比 | 有 |
| 留得住 | 退货率 | 非回收的退货金额 ÷ 实收 | 有；当日退列全为 0，不可用 |
| | 会员占比 | 会员销售行占比 | 弱：94% 行标为会员，区分度低 |
| | 新客、复购、客流、转化、ROI、用券 | — | **无**，虚线黄框；礼券两列全为 99/0 |

### 2.2 指标之间的关系（指标层的边）

指标不是彼此独立的，图上要能看出「拿什么换什么」：

- **分解树**（恒等式，实线）：实收 = 订单数 × 连带率 × 单件克重 × 每克实收。点「活动增量」可以展开成这四段，看增量主要来自哪一段。
- **取舍边**（相关，实线带「推断」）：每克让利 ↔ 单件克重、每克让利 ↔ 毛利率、以旧换新率 ↔ 连带率。

8 月数据里已经能看到的例子（一般足金类）：

| 优惠 | 每克实收 | 相对一般開單 | 单件克重 | <10 克占比 | 单均行数 | 含回收订单 |
|---|---|---|---|---|---|---|
| 一般開單 | 1087.4 | — | 8.48 | 76% | 1.42 | 11% |
| H-克减30元 | 1069.4 | −18 | 5.88 | 86% | 1.10 | 0.2% |
| H-克减50元 | 1033.2 | −54 | 18.43 | 38% | 1.69 | 0.4% |
| 七夕克减50 | 1044.3 | −43 | 8.41 | 76% | 1.16 | 0.2% |
| H-金色星期二 | 1083.7 | −4 | 12.46 | — | 2.53 | 100% |

- 克减50 的单件克重是一般開單的 2 倍以上，推断有克重门槛，力度换来的是大件。
- 金色星期二的订单 100% 带回收金，推断是以旧换新活动，它该看「以旧换新率」，用「每克让利」衡量它会判错。这正是中心要可切换的理由。
- 各优惠的每克牌价不同（1085.6～1104.7），说明成交日期不同、金价不同。每克比较必须**同日对齐**，否则让利里混着金价波动。

## 4. 交互

智能洞察模式（见第 6 节），左图右侧栏。

- **顶部**：目标指标切换（7 族下拉，默认「活动增量」）＋ 优惠筛选（全部 / 某个优惠，默认全部克减类）＋ 货类（默认一般足金类）。
- **点指标节点**：展开分解树，侧栏显示该指标的口径、8 月总值、按优惠排行。
- **点维度节点**：侧栏只放事实，包括取值分布、门店数、样本量、该维度下的指标值表，不下结论。
- **点连线**（维度 → 指标）：侧栏三段——
  - **依据**：该维度不同取值之间指标的差距（例如「购物中心 vs 街铺，每克让利差 12 元」），以及差距在各优惠间是否方向一致。
  - **异常**：偏离同层中位数超过阈值、且样本够大的格子，例如「某大区克减50 的单件克重反而低于一般開單」，附可能原因（货结构、期次短、门店少）。
  - **推荐**：该维度表现最好的取值，加上和它搭配最好的另一个维度（两两交叉里排第一的组合），措辞固定为「8 月里这种搭配表现最好」，不说「这样设会最好」。
- **连线粗细** = 关系强度（见 5.2）；实线 / 虚线 / 黄框按第 3 节规则。
- **侧栏底部两个按钮**：「问一问」（what-if）和「按这个建活动」。

## 5. 计算

### 5.1 两层本体

- **基础本体**（数据层）：从 `SEMANTIC_DIMENSIONS` + 新增的指标目录生成。实体 time / store / product / offer / line，带依据档位。图上「数据底座」页签展示截图那种表关系，并标明：实际只有一张宽表，其余 7 张是周大福目标结构（虚线）。
- **业务本体**（关系层）：目标指标、维度分组、指标分解与取舍边、维度→指标连线。用一份 TypeScript 常量定义结构，数值由离线计算填充。

### 5.2 连线怎么算

对每个（目标指标 M，维度 D）：

1. 一条分组查询：按 D 的取值 × 是否活动（活动 = 所选优惠，对照 = 一般開單）× 日期汇总基础字段（实收、克重、件数、牌价、毛利、订单、回收订单）。只取两边都有成交的门店（已有 `commonStores`）。
2. 每个 D 取值算活动和对照的 M，差值按日对齐后再合并。
3. 强度 = 各取值差值的极差 ÷ 全体差值的标准误，再按样本量打折；低于阈值画细灰线，并标「关系弱」。
4. 异常 = 差值偏离中位数 > 2 倍 MAD 且行数 ≥ 500。
5. 推荐 = 该维度最优取值；再和其余维度两两交叉，取最优组合（每格行数 ≥ 500）。

计算量：约 15 个维度 × 一次分组查询，指标由同一批基础字段推出，不用每个指标各查一次。只在 Agent 服务启动或数据集变更时算一次，结果存 `insight-graph-<datasetVersion>.json`（放 evidence 目录，带 SQL 和参数）。页面点击不再查库。

### 5.3 文字谁写

- 节点和连线的数字、排行、异常格子、推荐组合：**代码算**。
- 侧栏三段话：第一版用代码模板拼；后续可以交给模型润色，数字沿用自由正文的引用填值，模型不能改数。

## 6. 两种模式：智能洞察 / 智能问答

洞察和问答是同一份数据、同一套语义层的两种用法：没想好问什么时看图（洞察），有具体问题时直接问（问答）。两者放在同一个工作台里，用顶部的分段开关切换，不拆成两个页面。构建（ICS-1811）不属于这两种模式，是从任一模式都能进入的下一步。

| | 智能洞察 | 智能问答 |
|---|---|---|
| 适合 | 没有明确问题，想先看哪里有机会 | 有具体问题、what-if |
| 主体 | 关系图谱 + 侧栏 | 现有营销分析对话（`AnalyticsWorkspace`） |
| 数据 | 离线快照，点击不查库 | 实时查库，每问一次跑计划 |
| 出口 | 问一问、按这个建活动 | 回答里的维度回图上看、按这个建活动 |

规则：

- **入口**：`/analysis?mode=insight|qa`。直接进入时默认洞察；从侧栏打开历史对话时进问答。开关状态写进 URL，刷新不丢。
- **切换不丢状态**：两个模式都保持挂载，切换只是隐藏。图上选中的节点、连线，以及对话里输到一半的问题，切回来都还在。
- **洞察 → 问答**：侧栏的「问一问」等于带上下文切到问答。输入框上方出现一枚上下文标签（例如「正在看：克减50 × 城市级别 → 每克让利」），用户可以删掉；发送时把指标、维度、选中取值作为结构化上下文传给计划，而不是拼进问题原文。直接点开关切过去时不带上下文。
- **问答 → 洞察**：回答用到的指标和维度（从计划里取）在回答下方给一个「在图上看」，切到洞察并高亮对应的中心指标和连线。图上没有的维度（例如单个门店）不显示这个入口。
- **what-if 只在问答里做**，例如「克减 50 改成 40 会怎样」。只能用历史上相近的力度给一个区间，并说明 8 月只有 30 和 50 两档，40 没有直接样本。

## 7. 和构建、发布的衔接

- **问一问**：见第 6 节。
- **按这个建活动**：新建 ICS-1811 会话，把推荐整理成一句**草稿话**放进输入框（例如「七夕在一二线购物中心店做一般足金克减50」），由用户改完再发出去。不直接写事实层：日期、门店、力度都属于人定字段，必须是用户说的话（CLAUDE.md「人定字段不能默认」）。
- **发布**（演示壳）：读 ICS-1811 填写值，展示提交前自查清单和「已提交（演示）」状态，再给一个「活动结束后回洞察看效果」的入口，把闭环画完整。不连接 1811/1815/1816。

## 9. 已知限制（侧栏页脚常驻）

- 只有 8 月一个月，结论是同月横截面对比，不是前后对比；优惠不是随机分给门店的，参加的门店本身可能就不一样。
- 一般開單作对照是推断；门槛、叠加规则缺失，克减金额是从名称解析的。
- 毛利、牌仔价口径待确认；会员标识区分度低；没有客流和用券数据。

拿到 `Discount` 规则表或 7、9 月数据后，「参数」一支能转为实线，「依据」可以做前后对比。
