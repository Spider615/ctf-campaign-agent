# 内部用量、实际账单与会话执行记录设计

日期：2026-10-25。

状态：用户已明确首版功能和账单来源；本文为可评审设计，尚未实现。DeepSeek 官方账单明细的自动读取合同尚未验证，不能宣称已能自动同步实际费用。

2026-10-26 补充：模型有两个渠道，DeepSeek 官方接口和句子互动统一模型网关（Claude），用户确认两个渠道的用量和费用各算各的，费用按天对账，渠道在部署时按 `AGENT_PROVIDER` 二选一（沿用现状，不做按请求切换）。

## 1. 用户确认的范围

管理端供我们内部交付和产品同学使用。首版记录 Token 和实际费用，查看客户提出的问题、完整多轮对话和整个执行过程，并显示每次调用真实使用的厂商和模型。

模型渠道有两个：DeepSeek 官方接口，以及句子互动统一模型网关（Claude）。两个渠道的 Token 和费用分开统计、分开展示，不合并成一个总数。DeepSeek 渠道的费用直接接 DeepSeek 官方平台的账单明细；句子互动渠道的费用来源待确认（见第 9 节）。模型单价计算和 SDK 估算费用不进入实际费用统计。数据导入维护、质量工单、Skill 编辑发布和多客户平台管理不属于首版。

## 2. 已核对的现状

- `conversation_thread` 按浏览器访问标识和对话范围存整条对话，供前端恢复；它不是可信的模型用量账本，也不提供真实客户账号。
- `app/lib/tool-trace.ts` 已有真实工具步骤、状态、摘要和耗时；分析、附件与活动创建存在不同执行入口。
- `agent/analysis-plan-run-turn.ts` 已在仓库外保存部分分析审计记录，但缺少覆盖所有入口、贯穿会话和模型调用的统一记录。
- `agent/openai-bridge.ts` 转换部分上游 Token 字段，当前运行器没有统一持久化这些用量。
- `agent/model-gateway.ts` 的 `modelConfigFromEnv` 按 `AGENT_PROVIDER` 在进程级二选一：`deepseek` 时 SDK 直连 `https://api.deepseek.com/anthropic`，中间没有本项目代码；`juzi` 时 SDK 先到本机转换层，再转发到句子互动网关，网关 404/503 时换同厂商可用模型重试一次。
- 转换层把网关不提供的缓存写入 Token 填成 0（`agent/openai-bridge.ts` 的 `usageOf`），这个 0 不是上游观测值。
- 当前本地配置为 DeepSeek 官方接口。`agent/analytics-model.ts` 为 SDK 兼容使用 Claude 名称；官方映射合同明确此类名称可对应 DeepSeek 模型，不能据 SDK 别名认定厂商是 Anthropic。
- 本地 SDK 类型说明：`modelUsage` 和 `total_cost_usd` 是累计估算；不能当实际账单，也不能重复叠加同一累计结果。

这些是代码和本地配置核对，不构成线上部署或真实账单接通证明。

## 3. 页面

### 3.1 统计总览

入口 `/internal/stats`。提供日期范围、业务入口、厂商和模型筛选。

- 问答轮数、模型实际请求次数、Token 用量、执行耗时。
- 分别统计完成、部分回答、失败、取消、执行中和中断后状态未知。
- 输入与输出 Token 分开；缓存命中和写入作为有明确语义的子类展示，避免重复加总。
- 按渠道分栏：DeepSeek 官方和句子互动网关的 Token 与费用各自汇总，不跨渠道加总。
- 实际费用按渠道、按账单原币种汇总，显示账单覆盖周期、最近成功同步时间和可归属到本项目的范围。
- 展示用量采集完整度与账单匹配情况；未采集、待对账或不适用不显示成零。
- 支持按厂商和真实模型查看用量、费用分布，再进入具体会话。

日期选择默认采用北京时间。对账仍保留官方账单原始时区和区间，不用不同边界的日期直接匹配。

### 3.2 会话列表

入口 `/internal/conversations`。按日期、问题关键词、厂商、模型、业务入口和执行状态搜索。

每条展示匿名访客编号、会话标题、最近问题、问答轮数、Token 和执行耗时。账单按天对账，会话不显示金额。

首版不把浏览器访问标识称为真实客户人数。内部测试流量与客户入口流量单独标记；不能凭问题文本猜测身份。

### 3.3 会话详情

入口 `/internal/conversations/[id]`。

- 按实际时间展示全部已采集用户提问和公开最终回复。
- 每轮展示执行状态、总耗时、用量完整度和账单匹配情况。
- 展开真实执行时间线：加载的 Skill、模型请求、数据库与附件工具、图表、公开结果摘要、错误和重试。
- 每次模型请求展示接入渠道、真实厂商、请求模型、上游返回模型、请求/响应编号、Token 和耗时。兼容别名放在可展开技术详情中。
- 工具展示经允许的参数摘要、结果摘要和证据入口；不保存隐藏思考、系统提示词、完整工具入参、连接凭据或密钥。
- 并发调用显示各自起止时间和父子关联，不把并行耗时相加成整轮耗时。

## 4. 采集与关联

统一关系：浏览器访问标识 → 会话 → 问答轮次 → 执行步骤 / 模型请求 → 官方账单记录。

问答轮次和模型请求编号由服务端建立。客户输入及请求到达后立即记录，结果、步骤和用量随执行增量保存。客户端提交的整条对话 JSON 不作为费用或执行事实的权威来源。

覆盖智能问答、附件问答及其中的经营分析和图片调用、洞察问答、活动创建。嵌套分析绑定原轮次，保留父调用关系，不重复算成新的客户问题。测试脚本不混入客户统计。

采集落点为 Node 的统一请求和模型边界。模型边界是本机回环上的一层：句子互动渠道复用现有转换层；DeepSeek 渠道新增一层只透传、不改请求体的本机代理，记录请求模型、上游返回模型、响应编号、usage 和耗时。两个渠道由同一套代码写同一种记录，不再从 SDK 事件中拼逐请求用量。管理页面经有内部授权的 API 查询。SDK 启动次数与真实上游请求次数分别记录。统一记录对未来运行器更换保持独立，不把当前固定分析步骤写成统计合同。

在上游返回的用量终态可取得时，按请求或响应编号更新同一记录。SDK 汇总只作为校验来源，不与逐请求用量重复相加。未取得终态的流式调用保存已知信息并标记不完整。

失败、用户停止、网络断开和自动重试均保留已有记录。重试是独立请求，不覆盖前一次；SDK 合成的错误消息不当成已收到真实模型响应。进程重启后未收尾记录标为中断且用量可能不完整，不凭时间推算完成或费用。

## 5. 厂商与模型身份

渠道在部署时二选一，但切换配置前后的历史记录会并存，所以每次模型请求仍要保存接入渠道（`deepseek` / `juzi`）、厂商、配置请求模型、实际发往上游的模型、上游返回模型及其确认依据。

DeepSeek 官方兼容接口中的 `claude-sonnet*` / `claude-haiku*` 映射到 `deepseek-flash`，`claude-opus*` 映射到 `deepseek-v4-pro`。DeepSeek 渠道的请求显示 DeepSeek 和已确认的 DeepSeek 模型，不因协议或 SDK 名称显示为 Claude。句子互动渠道的请求按转换层实际发往上游的模型记录，厂商取网关 `/models/status` 的 `owned_by`；回退后的模型单独成一条请求记录。

网关回退和同轮不同模型分别记录。上游没有返回的 Token 子项（例如句子互动网关的缓存写入）记为未提供，不记 0。上游未公开的具体部署版本不作推断；身份依据不足时显示未确认，不能只按模型名称前缀猜厂商。

## 6. 实际费用

两个渠道的费用各算各的：来源、币种、粒度和对账状态都按渠道分别保存和展示，不跨渠道加总，也不用一个渠道的单价去估另一个渠道。句子互动网关渠道的费用来源确认前，该渠道只展示 Token，费用显示为来源未接入。

费用按天对账：实际费用的最小粒度是「渠道 × 账单日」，不到会话和单次请求。会话列表和会话详情只显示 Token，不显示金额，也不按 Token 比例把当天费用摊到会话。总览按天并列展示当天 Token 和当天实际费用，两者都按账单日边界切分。

### 6.1 DeepSeek 官方实际账单

实际金额只来自可验证的官方扣费明细，保留账户范围、原始账单标识、金额原文、币种、计费周期和获取时间。不得由 Token 乘单价或余额前后差额生成实际扣费。

自动同步的实施前置条件是：验证官方账单读取入口的鉴权、明细字段、分页、时间边界、迟到/修正处理和项目归属能力。当前公开文档已确认 `/user/balance` 返回余额；它不提供本设计需要的逐请求账单合同。不能虚构一个账单 API，或把个人浏览器登录态作为部署时的长期凭据。

对账规则：

1. 官方明细有可验证的请求编号时，优先精确关联，并检查账户、模型和币种一致性。
2. 只提供账户、API Key、日期或模型聚合时，只展示该粒度的实际金额；不按 Token 比例分摊给会话。
3. 账户同时承担其他应用用量时，只纳入能明确归属本项目的记录。不能把账户总消费当成本项目消费。
4. 未关联的调用显示待对账；官方明细粒度无法支持会话关联的，明确显示无法归属到会话。保留已匹配、冲突和不适用状态。
5. 同步按官方记录标识幂等。修正和退款保留关联与历史，不重复累计，不覆盖本地已观测 Token。

金额使用精确十进制和原始精度，不能统一先舍入到分而丢失小额调用。不同币种分别汇总。

## 7. 内部访问和历史数据

首版提供独立的内部管理员登录和签名会话，管理页面和 API 都在服务端校验内部权限。现有客户访问标识不能作为管理员身份；客户首页不增加管理入口。客户问题及执行记录在服务端私有保存，不进入代码仓库或默认镜像。

旧会话只展示确实存在的对话和轨迹。历史 Token、厂商和费用无法追溯时标记未采集。客户侧删除对话不反向篡改已经发生的用量和官方财务事实；内部记录的保留与删除使用独立管理权限。

## 8. 验收

- 同一会话的两次提问分别关联到正确轮次；并发会话、嵌套分析和迟到事件不会串号。
- 单次模型响应在流式事件、assistant 和 SDK 汇总中多次出现时不重复计数。
- 完成、失败、取消、断连和重启都保留已发生的记录；未完成用量不补零。
- DeepSeek 兼容别名正确展示真实厂商和模型；句子互动网关的回退及多模型分别展示。
- 两个渠道的 Token 和费用分开统计，总览不出现跨渠道合计；上游未提供的 Token 子项不显示成 0。
- 官方账单匹配能核对金额、币种、账户和原始标识；重复同步、迟到账单和账单修正不重复累计。
- 官方只提供汇总时，页面保留汇总粒度，不伪造逐会话实际费用。
- 未授权不能读取管理页面、客户提问或管理 API；日志和导出无密钥及隐藏思考。
- 用真实服务和真实模型验证提问、执行记录、Token、刷新恢复；账单自动同步另须真实官方明细验收。页面能打开或余额查询成功不代表账单接通。

## 9. 待确认

- DeepSeek 账单日的时区边界，以及日账单是否再按模型或 API Key 拆分。若不按 Key 拆分且账户还有其他应用在用，当天金额不能算作本项目费用。
- 句子互动网关渠道的费用以什么为准，网关是否提供按 key 或按请求的用量、账单接口。
- DeepSeek 后台日账单是手动导出还是能经接口读取。
