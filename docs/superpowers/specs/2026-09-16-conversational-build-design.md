# 对话式搭建：去掉确认步骤，由 Agent 主导追问

日期：2026-09-16。补充并部分取代 `2026-09-16-ics1811-sop-agent-design.md` 第 4 节（追问与轮次）、第 8.1 节（复述确认）和第 13.2 节的 P1、P2、P10（现行取值见 `app/lib/reference/open-questions.ts`）；`2026-09-16-light-ai-workspace-design.md` 里的工具表以 `app/lib/tool-trace.ts` 为准。

## 为什么改

用户反馈：「去掉这个点击确认的步骤，我要改成对话式的，而且感觉 agent 很死板……给用户的感觉是在对话的过程中把营销活动创建出来」。

死板来自代码，不是模型：

- 追问由代码出卡片，一次列出全部缺项，标「第 1 轮 · 最多 2 轮」，模型不能提问（开卡时问句被删）。
- 一句话说全的需求，对话里依次出现：模型逐条复述 → 复述卡片（6 条要点 + 折叠默认项）→「确认无误，生成填写值」按钮。同一份信息出现三遍。
- 顶部五步进度条（说清需求 → AI 分析 → 补齐信息 → 核对复述 → 生成填写值）像表单向导。

## 决策

- **D5 齐了直接建好。** 人定项齐了、校验没有阻断，这一轮直接生成填写值（`agent_fill_sheet`，附代码写的摘要），不再单独确认。之后的修改同步重算并再出一份。
- **D6 人定项由 Agent 提议、用户点头。** 人定项仍然不能默认；Agent 可以说出一个具体值（「让扣点和回款率一般没有，提成按实际售价算，这次也这样？」），用户回「行」「对」才记下。

## 分工

| 谁 | 决定什么 |
|---|---|
| 代码（`questions.ts` `gapsOf` / `planNext`） | 还缺什么、有没有阻断、齐没齐（`collect` / `ready` / `out_of_scope`） |
| 代码（`turns.ts`） | 齐了就生成填写值；模型没登记要问什么时兜底补问；整句只是点头时直接按提议记 |
| 模型 | 先问什么、一次问几项（1–3）、怎么措辞、要不要提议 |
| 守卫（`facts.ts` / `proposals.ts`） | 事实只来自用户原话或用户同意的提议；提议值按代码表和取值范围校验，文字由代码渲染 |

## 流程

1. 模型 `extract_campaign_facts` → `analyze_campaign_state`（返回缺项题号、`complete`）。
2. 还缺：模型 `ask_campaign_questions({questions, proposals?})` 登记，再在回复里用自己的话问。登记内容存在这条 `agent_text` 的 `asking` / `proposals` 上，下一轮的短回答（「没有」）和点头按它对。
3. 用户整句只是点头（`isPureAgreement`）：编排器在调模型前 `acceptProposals`，来源记 `via: "proposal"`，模型拿到已记好的草稿。点头又改了一部分：模型用 `accept_campaign_proposals`（只列同意的题号）+ `extract_campaign_facts`。
4. `planNext` 为 `ready`：编排器生成填写值消息；模型用两三句话说建好了，不问确认。
5. 模型没登记问题时的兜底：记下了东西、回复里没有问句 → 按 `QUESTION_PRIORITY` 补问前两项；回复里有问句 → 不算在问任何一项（原来按全部缺项对，验证时复现过「还没」被记成没有让扣点）；只是在回答疑问 → 上一句的问题继续有效，提议不延续（用户回「好的」是知道了，不是同意）。

## 验证后补的守卫（2026-09-16）

- 提议带原值 `before`：用户之后自己改过这几项，提议作废；已填项也可以提议改值（建好后「往后推一周」这类要换算的改动）。
- 二选一问法（「还是」「哪种」且两个选项都出现）下登记的提议丢弃；提议问法要求肯定问法。
- 纯点头不含问号和求证（「嗯？」「对吧」不算）；`accept_campaign_proposals` 挡「不行」里的「行」，混合句必须列题号。
- 上一句带提议的题，短回答不走是/否兜底；提议日期不能早于今天；Q5c 只能提议「有」；用户说「不知道」的让扣点不能提议没有。
- 门店「再加 / 不做了」按增减合并；标语原文优先取引号内；让扣点、回款率可以只改一项；「不需要计算折上折」按不计算记。
- 只改对外文案时不重复出填写值；预采纳后 Agent 失败，轨迹里的「按提议记下」改记为未保存。

能提议的题：Q1、Q2、Q3b、Q3c、Q3d、Q4、Q4a、Q5a、Q5b、Q5c、Q6a（只能提议不加）。优惠方式和力度（Q3、Q3a、Q3e）、标语原文、法务确认（Q6b）要用户自己说。

## 去掉的

- 回合类型 `card`、`confirm`；工具 `build_campaign_readback`、`confirm_campaign_readback`。
- 追问卡片、复述卡片、确认按钮、五步进度条、轮次上限（`MAX_ROUNDS`）。
- `finishAgentTurn` 删问句。

## 旧会话

`agent_round_card`、`agent_readback`、`user_card_submit`、`user_event: confirm` 仍能解码，只读展示；旧工具名仍能通过执行记录校验。旧会话打开时按新规则重算：齐了就是「已建好」。
