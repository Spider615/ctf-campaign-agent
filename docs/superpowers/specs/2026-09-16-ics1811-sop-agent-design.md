> 依据：飞书《优惠开单活动创建 SOP》（https://juzihudong.feishu.cn/wiki/UYmkwllyli2QDikze8tc4WBpnac）第一、二、三、五、七、八、九部分及其 16 张截图；第四部分（1816 批量导入）、第六部分（审批与 1815 跟进）不在范围。下文「§9(二)」指 SOP 第九部分（二），截图编号如「03a」见附录 A。文中「§」只指 SOP 章节，本文自己的章节写作「第 X 节」「X.Y 节」。
>
> 本文取代 `2026-09-15-ctf-campaign-agent-design.md` 与 `2026-09-15-conversational-campaign-flow-design.md` 中与本文冲突的全部内容（营销方案层、五维拆单、不编造码表、问题集、校验规则）。两份旧文档保留作历史记录。

## 0. 为什么改

SOP 第九部分给出了 demo 规格：只做 ICS-1811 单条新增；人定字段必须问、不能填默认值；AI 定字段不单独问、在白话复述里确认；信息不全时最多追问两轮；代码表 demo 阶段编造并集中在一个配置文件；提交前校验用代码做。现有实现按旧设计做，和这份规格结构性冲突：

| 现状 | SOP 要求 | 证据 |
|---|---|---|
| 按「批次 × 市场 × 渠道 × 门店 × 档位」笛卡尔积拆成 N 条 ICS 单 | 一个 1811 活动勾选多家分行，挂多条明细；完成新增后按号头展开成多行 | `split-orders.ts:39-43`；§3(一)、§3(三)5；03h |
| 模型写方案四段文案，标语不能为空 | 标语只照抄法务确认过的原文，AI 不写 | `tools.ts:187-188`；§9(二)6 |
| 不编造内部码表，区域、货类等输出「待界面选择」 | demo 编造代码表，集中放一个配置文件 | `code-tables.ts:158-194`；§9(一) |
| 「能否叠加」决定是否计算折上折，「折上折」算叠加依据 | 计折上折是销售提成口径，人定必问；「折上折」「可叠加」字样不算回答 | `evidence.ts:48`、`clarify.ts:86`；§9(二)5 |
| 追问 14 项（由头、人群、顾客动作、市场、支付限制等），轮数无上限，「都可以不填」 | 只问 §9(二) 的 6 问，最多两轮，(二) 以外只在复述确认 | `topics.ts:139-196`、`clarify-card.tsx:288`；§9 验收标准 |
| 信息齐了模型直接写方案，没有复述确认 | 白话复述 → 用户确认 → 输出填写值 | `prompt.ts:26`；§9(三) 复述示例 |
| R17 折扣率须大于 0；R3 名称超 13 字只是提醒 | 黄金以旧换新免工费填 0.0；名称不超过 13 字是硬规则 | `validator.ts:22-24,92`；§5(三)4、§7 |
| 活动分组取「门槛优惠 / 增值服务」，R16 永远不触发 | 3)其它优惠 / 17)货品回购 / 19)增值服务，铂金和钻石以小换大改 17 | `workspace-state.ts:190`、`validator.ts:80-86`；§5 表 |
| 让扣点、回款率在活动级 | 每条明细各填一次 | `types.ts:120-121`；§3(三)3；03c |
| 数字守卫要求原话有阿拉伯数字 | 「没有让扣点」填 0、「免工费」填 0.0、「钻石不打折」填 1 都是合法回答 | `ai-schemas.ts:333-337`；§9(二)5、§5(三)4、§5(四)3 |

## 1. 范围与已定决策

**做**

1. 一句话需求 → 最多两轮追问 → 白话复述 → 用户确认 → 输出 1811 填写值（活动信息 + 结算说明函 + 明细 + 操作步骤）、建完后待办、自查清单。
2. 一个会话只做一个活动（一个审批编号内的一个「新增」）。
3. 编造代码表集中在 `app/lib/campaign/ics1811/codebook.ts`，每个值标来源（截图 / 指引文字 / 导入模板 / 编造）。
4. 沿用现有会话、版本、消息持久化和撤销、恢复。

**不做**

- ICS-1816 批量导入、指定货品编号。
- 营销方案层：对外传播名、人群、由头、顾客动作、「只看到 → 不建 ICS 单」路径全部删除。需求里没有任何成交优惠时，回复「这不属于 1811 优惠开单活动，demo 暂不处理」。
- 连接任何生产系统；真实上传结算说明函（只给建议文件名）；在 1815 里操作（只列待办）。
- 一个会话多个活动、审批编号分组。
- 分克重段每整克优惠（§9(四) 明确不支持），以及黄金工费打折、满件折、满折、每满返、联单（SOP 没有参数栏截图，提示人工录入）。

**已定决策**

| 编号 | 决策 | 理由 |
|---|---|---|
| D1 | 去掉营销方案层 | §9 范围只有 1811 单条新增；方案层的「标语」与 §9(二)6 冲突 |
| D2 | 两轮追问后人定项仍缺：复述里列出仍缺项，确认按钮禁用，不生成填写值；用户打字补齐后重新复述 | §9 划分标准「需求没写时必须在对话中问，不能填默认值」 |
| D3 | 没有参数栏截图的优惠类型：满减、每满减、金价每整克减免、售价固定折扣按推断的栏位输出并标「栏位推断」；其余 5 类提示人工录入 | 满减是否累加、每克还是每整克、纯打折不能改价，都是 §9 点名要处理的场景 |
| D4 | 一个会话只做一个活动；需要拆成多个活动时提示用户分开建 | §3(五) 只给了共用审批编号的操作，没给判断标准 |

## 2. 验收标准

| 编号 | 标准 | 判定方式 |
|---|---|---|

## 3. 1811 填写模型

归属一列：**人定**（§9(二)，对应问题编号见 4.1 节）、**AI 定**（§9(三)）、**待确认**（§9(四) 含义待确认，按 demo 默认处理并在复述里标出）。

### 3.1 活动信息（点「新增」前，顺序按 05g）

| 字段 | 取值 / 格式 | 归属 | 规则 | 出处 |
|---|---|---|---|---|
| 活动名称 | 文本，不超过 13 字，无特殊字符 | AI 定 | 模型按需求起草，代码校验；不通过时用模板生成 | §3(一)、§7、§9(三) |
| 活动标语 | 文本，可空 | 人定 Q6 | 只照抄法务确认过的原文；用户说不要或法务没确认 → 留空 | §3(一)、§7、§9(二)6 |
| 活动内容 | 文本，无特殊字符 | AI 定 | 按需求概括活动说明，只复述事实层里已有的数字 | §3(一)、§9(三) |
| 活动日期 | 开始、结束（结束当天有效） | 人定 Q1 | 输出 YYYY-MM-DD | §3(一)、§9(二)1 |
| 线上/线下 | 1)线上活动 / 2)线下活动 | 待确认 | 原话提到线上或电商选 1，否则选 2 | §9(四) |
| 优惠类型（活动级，即「优惠性质」） | 0)一般销售 / 1)营销活动 | 待确认 | 一律选 1)营销活动 | §3(一) 注意栏、§9(四) |
| 品牌 | 页面默认「周大福」 | AI 定 | 原话提到单一品牌照填；没提用周大福并在复述写明；不按门店推断；提到多个品牌 → 复述里请用户指定（阻断） | §9(三) |
| 计折上折 | 不计算折上折 / 计算折上折 | 人定 Q5b | 页面默认值不能直接用 | §3(一)、§9(一)、§9(二)5 |
| 是否参与打折 | 可参加活动货类 | 待确认 | 用页面默认 | §9(四) |
| 预售时间 | 0–7 天 | 待确认 | 填 0 | §9(四) |
| 周期 | `0`，或 1–7 用英文逗号分隔（7 为周日） | AI 定 | 原话提到每周几由代码换算；没提填 0 | §3(一)、§9(三) |
| 审批流 | 1 周大福审批 … 8 EJ 审批 | AI 定 | 单一品牌按品牌对应；多品牌且没指定时不选，复述写明涉及的品牌；不自动选电商审批 | §3(一)、§9(三) |
| 货品范围（页面有此栏时） | 0 全部货品 … 6 奥莱专供 | AI 定 | 没提填全部货品；提到照原文换算 | §9(三) |

| 是否凭券使用（页面有此栏时） | 否 | 待确认 | 填否 | §9(四) |
| 区域 | 0)全国 … 230)藏品区 | 人定 Q2 | 由分行在代码表里反查 | §3(一)、§9(二)2 |
| 分区 / 小区 / 城市 | — | — | 不选（§3(一) 截图示例只选了区域和分行） | §3(一) |
| 分行 | 店号，多选 | 人定 Q2 | 至少 1 家，都在代码表内且属于所选区域 | §9(二)2 |
| 支付方式 | 默认 14 项（含 GLP 积分抵现） | AI 定 | 用默认组；原话要求去掉或加入时照改 | §3(一)、§9(一)、§9(三) |

### 3.2 结算说明函（点「新增」成功后上传）

- 只在分行 ≥ 2 家时出现。有没有结算说明函是人定 Q5c。
- 有：代码按「区域+分区+简写店名+店号+月份」生成建议文件名，每家店一个，不重名，最多 30 个；月份取活动开始月份。规则与示例「闽深A区3319东门茂业4月」的顺序不一致，先按示例顺序（见第 13 节）。
- 用户回答没有：记提醒，不阻断。
- demo 不真正上传，只在操作步骤里写「上传后每个文件都要看到上传成功」。
- 出处：§2、§3(二)、§9(二)5；03b。

### 3.4 限制条件

- 需求没提：不输出，填写值里写「其余限制条件留空（数值栏保持 0）」。
- 需求提到：照原文换算写入对应栏。
- 提到了却换算不出代码（例如只给了系列名、款式名），或页面没有对应栏：复述里列为阻断项，用户给出代码或选「不限定」后解除（§9(三)）。
- 允许模号货类 demo 留空（§9(四)）。
- 格式：多个值用英文逗号；允许模号货类为单个值、1–3 个大写字母；不允许货组按「货组+货类」如 `15A,16A`（§3(三)4）。
- 不允许货组非空时醒目提醒范围不要过宽（§3(三)4 提示框、§7）。
- 版本差异：固定模式截图只有 9 栏（05a/05c/05e/05f），部分版本多「不允许货组」（03e/05d），浮动模式 03f 有 27 栏。只输出非空项；该栏不在基础 9 栏里时标「部分版本页面才有此栏」。

## 4. 问题目录与对话流程

> 已被 `2026-09-16-conversational-build-design.md` 取代：没有追问轮次和复述确认，缺什么由 Agent 在对话里问，齐了直接生成填写值。本节只供追溯。

### 4.1 问题目录

问题只来自这张表（§9(二)），代码写死，模型不能加题。问法取 §9(二) 原文。

| 编号 | 问法 | 什么时候出现 | 出处 |
|---|---|---|---|
| Q1 | 活动从哪天到哪天？ | 没有起止日期，或原话日期没有月日数字（如「国庆」「下周」） | §9(二)1 |
| Q2 | 哪些门店参加？ | 没有门店；只说了区域没说门店；门店对不上代码表（附候选） | §9(二)2 |
| Q3 | 怎么优惠、给多少？ | 没有优惠描述 | §9(二)3 |
| Q3a | 按类型问缺的参数：满多少？换大几倍？每个换大比例工费打几折？钻石本身打几折？每克减多少？ | 优惠类型已知，但缺该类型必需的参数 | §9(二)3 |
| Q3b | 门店能不能在这个折扣基础上改价、少打一点？（能改用浮动折扣模式，不能改用固定折扣模式） | 纯打折，没说能否改价。原话限定了售价类型时追加一句：浮动折扣模式限定不了售价类型 | §9(一)、§9(二)3、§9(三) |
| Q3c | 买满 2X 元时，是减一次 Y，还是减两次共 2Y？ | 满 X 减 Y，没说是否累加 | §9(二)3 |
| Q3d | 每克减 Z 元是按实际克重算，还是按单件重量的整数克算？ | 克减没说口径（买钻石享黄金克减除外，见第 5 节） | §9(二)3 |
| Q3e | 哪个货类对应哪个折扣？ | 多个货类、多个优惠值，没配成对 | §9(三) 明细拆分 |
| Q4 | 哪些货类参加？ | 没有货类，或货类说法有歧义（如「黄金」附候选）；铂金以旧换新、钻石以小换大不问 | §9(二)4 |
| Q4a | 销售时要不要转为 outlet 餐牌？ | 提到 outlet 货品 | §9(二)4 |
| Q5a | 有没有让扣点或回款率？没有就都填 0。 | 没提 | §9(二)5 |
| Q5b | 销售提成按实际售价算，还是按实际售价 × 折扣算？ | 没提提成口径；「折上折」「可叠加」字样不算提过 | §9(二)5 |
| Q5c | 多家门店的活动有没有结算说明函？ | 分行 ≥ 2 且没提 | §9(二)5 |

### 4.2 轮次规则

- **第 1 轮**：出卡时，把当时全部缺项一次问完，包括首句已经触发的追问。依据：SOP 原文第二轮只放「依赖第一轮回答才需要问的」；首句已写「9 折」时，问浮动还是固定并不依赖第一轮回答。
- **第 2 轮**：只问由第 1 轮回答新触发的追问，以及第 1 轮没答的人定项（标「上一轮没回答」）。
- **两轮用完仍缺**（D2）：不出第 3 张卡片；复述里列「仍缺」，确认按钮禁用；用户打字补齐后重新复述。
- **复述之后的修改**引出新缺项：计入两轮上限；还有轮次就出下一轮卡片，没有就在复述里列仍缺。
- 已用轮数 = 消息记录里追问卡片的最大轮次。状态全部从消息和草稿推出，不另存，撤销、恢复不会重置轮次。
- 实现：`planNext(draft, roundsUsed, checks)` 返回 `ask(round, questions)` / `readback(canConfirm, missing)` / `out_of_scope(reason)` 三种结果之一，纯函数。

### 4.4 SOP 没规定的情况

| 情况 | 处理 |
|---|---|
| 用户对人定问题回答「不知道」「按惯例」 | 不填默认值，该项仍缺，按轮次规则处理；「不知道」不等于「没有」，让扣点不能因此填 0 |
| 一句话里有多个活动（两段日期、线上加线下、不同门店不同玩法、同时需要 17 和 19 分组） | 列出识别到的部分，请用户先说其中一个活动，另一个新建会话（D4）；不写入冲突的部分 |
| 涉及多个品牌 | 审批流不选；品牌栏只能单选，复述里请用户指定品牌（阻断，建完后 1815 改不了品牌，05b） |
| 只写了月日没写年份 | 取今天之后最近的日期，复述写明年份 |
| 门店名对不上、有同名门店、表外店号 | 算 Q2 没说清，列候选；表外店号不接受（不能编造它属于哪个区域） |
| 只说区域不说门店 | 问 Q2 具体门店，列出该区域候选，不展开为全部分行 |
| 用户让 AI 想一句标语 | 回复 AI 不写标语，只能填法务确认过的原文 |
| 需求里有下拉里没有的玩法（送赠品、第二件半价、积分加倍等） | 回复 1811 明细优惠类型里没有对应选项，需先确认 ICS 是否支持；支持的部分照常处理 |
| 用户问字段是什么意思 | 模型直接回答，不调工具，不出卡，不计轮次 |

**推导规则（`derive.ts`，纯函数）**

1. 玩法识别由代码按原话关键词判定，模型给的类型只作参考，冲突时以代码为准：
   - 铂金以旧换新：`/铂金/` 且 `/以旧换新|换购/`
   - 钻石以小换大：`/以小换大/`
   - 黄金以旧换新：`/黄金|足金/` 且 `/以旧换新/`
   - 买钻石享黄金克减：`/钻石/` 且 `/克减|每克/`
   - 满减类：`/满\s*\d/` 且 `/减\s*\d/`；克减：`/每克|克减/`；纯打折：`/\d+(\.\d+)?\s*折/` 且不属于以上任何一种
2. 买钻石享黄金克减的第二条固定为「金价每克减免」（§5(四)5），不问 Q3d，复述写明「按实际克重」。
3. 同一活动的明细需要不同活动分组（例如 17 和 19）时，记阻断「需要拆成两个活动分别建」（活动分组在 1815 里是活动级字段，05b）。
4. 不同货类折扣不同 → 按货类拆成多条明细（§9(三)）。
5. 业务大类、固定货类和号头、活动分组、建完后待办都由代码写入，来源 ai。

### 6.4 提示词要点（`app/lib/agent/prompt.ts`）
